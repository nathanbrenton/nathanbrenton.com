PURPOSE
-------
Clean, known-good walkthrough for the production email and server-monitoring
stack on web-prod-01.

This runbook now covers TWO deliberately independent mail roles:

1. Operational/status mail generated by this server and sent outward.
2. Public business/contact mail received for nathanbrenton.com and hiplingo.com,
   then forwarded to a separate contact destination.

It also records the nginx hidden-path hardening added after public scanners
requested paths such as /.git/config and /.env.

The August 18, 2026 update additionally records the Hiplingo public-media
filesystem boundary needed by metadata-editor's atomic media deployment.
That permission model matters operationally because nginx must remain
read-only while the dedicated media deploy identity must be able to create
temporary sibling directories during an atomic publication swap.

This document intentionally emphasizes final architecture, why each mail
technology is present, validated behaviors, safe rebuild/maintenance checks,
and operational boundaries. Troubleshooting detours are omitted except where
they explain an important security property.

DESIGN DECISIONS
----------------
1. Postfix is now a DUAL-ROLE MTA:
       - outbound operational mail; and
       - narrowly scoped inbound SMTP for public contact forwarding.

2. Postfix is NOT a general mailbox server:
       - no IMAP
       - no POP3
       - no user mailboxes
       - no submission service on TCP/587
       - no implicit TLS submission on TCP/465

3. Public SMTP listens only on:
       127.0.0.1:25
       45.32.88.137:25
   IPv6 SMTP is intentionally not enabled.

4. nftables is default-drop and explicitly permits inbound TCP/25 only after
   recipient validation, TLS, anti-relay behavior, SRS, DNS, and external
   client testing were completed.

5. Public recipient scope is intentionally explicit:
       operations/admin:
           admin@hiplingo.com

       business/public:
           info@nathanbrenton.com
           postmaster@nathanbrenton.com
           nathan@nathanbrenton.com
           info@hiplingo.com
           postmaster@hiplingo.com
           nathan@hiplingo.com
           licensing@hiplingo.com
           press@hiplingo.com
           accounting@hiplingo.com

       plus valid signed SRS bounce addresses only

   Unknown addresses receive SMTP 550 rejection instead of becoming a
   catch-all.

6. Unauthenticated arbitrary relay is forbidden. External relay testing
   returned SMTP 454. Localhost may relay because loopback is intentionally
   present in Postfix mynetworks for trusted local system submission.

7. Public contact forwarding uses SRS (Sender Rewriting Scheme). Forwarding
   commonly breaks the original sender's SPF because the final recipient sees
   the forwarding VPS as the connecting SMTP host. SRS replaces the envelope
   sender with a signed address under srs.nathanbrenton.com so SPF evaluates
   against the forwarding server and bounces can be safely reversed.

8. SRS does NOT make SPF align with the original visible From: domain for
   DMARC. Preserving the original sender's DKIM signature is therefore
   important; DKIM alignment can carry DMARC through forwarding even when the
   original SPF path would no longer align.

9. PostSRSd lookup ports 10001 and 10002 are loopback-only:
       10001 = forward sender rewrite
       10002 = reverse SRS validation/decoding

10. Public SMTP uses a dedicated Let's Encrypt certificate for:
        web-prod-01.nathanbrenton.com
    Postfix advertises opportunistic STARTTLS with smtpd_tls_security_level=may.
    The certificate renewal deploy hook reloads Postfix after renewal.

11. Operational sender identity remains separate:
        alerts@ops.nathanbrenton.com
    with independent SPF + DKIM + DMARC.

12. ADMIN_FORWARD_TARGET and CONTACT_FORWARD_TARGET are deliberately
    independent configuration responsibilities. They may currently resolve to
    the same real inbox, but changing one destination later must not change the
    other. ADMIN_EMAIL is the stable internal alias admin@hiplingo.com, not the
    real admin inbox.

13. No Gmail SMTP relay, Gmail App Password, or hosted mailbox provider is
    required for forwarding. The server speaks SMTP directly to recipient MX
    systems.

14. Monit CLI uses a root-only Unix control socket; TCP/2812 is not exposed.

15. Monit sends alerts with its built-in SMTP client directly to
    127.0.0.1:25. Production does NOT require a server-monitor-alert EXEC
    helper and does NOT require a /var/spool/postfix/maildrop sandbox
    exception.

16. The operational/admin destination has one canonical routing point:
        /etc/server-monitor/config      -> ADMIN_EMAIL=admin@hiplingo.com
        /etc/monit/conf.d/mail-alerts   -> set alert admin@hiplingo.com
        /etc/postfix/admin-forwarding.regexp -> ADMIN_FORWARD_TARGET

    Only the admin forwarding map changes when the real operations inbox moves.
    This remains independent from CONTACT_FORWARD_TARGET.

17. The public web roots are protected against hidden-file probes. A prior
    scanner request for /.git/config returned HTTP 200 only because the SPA
    fallback served index.html. Hash comparison proved the response was the
    normal app shell, and filesystem scans found no .git/config or .env files.
    nginx now returns 404 for hidden paths such as /.git/* and /.env.


18. Hiplingo public media uses a dedicated deployment identity and a deliberately
    asymmetric filesystem boundary:

        /var/www/hiplingo.com
            root:hiplingo-media-deploy
            mode 3775  (SGID + group-write + sticky bit)

        /var/www/hiplingo.com/app
            root:hiplingo-app-deploy
            mode 2775

        /var/www/hiplingo.com/published-media
            owned by deploy-hiplingo-media after the first atomic deployment
            normal live mode 0755

    metadata-editor stages an upload as a sibling path such as:

        published-media.metadata-editor-incoming.<operation-id>

    The media deploy identity therefore needs write permission on
    /var/www/hiplingo.com itself, not merely inside the existing
    published-media directory.

    The sticky bit is important: group-write on the parent is required for
    sibling staging, but the sticky bit prevents deploy-hiplingo-media from
    renaming/removing the root-owned app entry.

19. nginx/www-data is intentionally NOT a member of hiplingo-media-deploy.
    Public media is served read-only through:

        /media/ -> /var/www/hiplingo.com/published-media/

    Public directories should be 0755 and public files should be 0644.
    Do not solve nginx read failures by adding www-data to a deployment group
    or by using chmod 777.

20. Private Library waveform binaries may intentionally be mode 0600. That
    private mode must NOT cross the publication boundary. metadata-editor's
    public-package writer normalizes copied public assets to 0644, and the
    production rsync layer independently enforces:

        directories -> 0755
        files       -> 0644

    This was added after the initial production deployment exposed
    waveform-peaks.wfp as mode 0600, causing nginx HTTP 403 responses.

21. The public URL is /media/, not /published-media/. The latter is the
    server-side directory name. Requests to /published-media/... fall through
    to the SPA route and are not the public media contract.

2B. PUBLIC CONTACT / FORWARDING DNS
----------------------------------------------------------------------

Production records:

nathanbrenton.com:

    MX 10 web-prod-01.nathanbrenton.com.

hiplingo.com:

    MX 10 web-prod-01.nathanbrenton.com.

srs.nathanbrenton.com:

    MX 10 web-prod-01.nathanbrenton.com.
    TXT "v=spf1 ip4:45.32.88.137 -all"

An A record for srs.nathanbrenton.com is NOT required in this design because
its MX explicitly points to web-prod-01.nathanbrenton.com, whose A/PTR pair is
already established.

Why the SRS SPF record exists:
    Forwarded mail leaves web-prod-01 with a rewritten envelope sender under
    srs.nathanbrenton.com. The destination receiver therefore evaluates SPF
    against the forwarding VPS and this dedicated SRS domain.

Validated end-to-end:
    - messages to both public info@ aliases arrived
    - visible To: remained the original info@ alias
    - Return-Path/envelope sender was rewritten to @srs.nathanbrenton.com
    - SPF passed
    - original sender DKIM remained signed/valid
    - neither test message landed in Spam

Important DMARC note:
    SRS repairs the SPF transport identity for forwarding, but the SRS domain
    is not the original visible From: domain. Therefore SPF alignment alone
    does not preserve the original sender's DMARC alignment. Keeping the
    original DKIM signature intact is valuable because aligned DKIM can still
    satisfy DMARC after forwarding.

---------------------------------------

File:
    /etc/postfix/contact-forwarding.regexp

The map's right-hand destination is the conceptual:

    CONTACT_FORWARD_TARGET

It is hard-coded independently from ADMIN_FORWARD_TARGET. The two targets may
currently be the same real inbox, but changing one must not change the other.

Current accepted business/public aliases:

    info@nathanbrenton.com
    postmaster@nathanbrenton.com
    nathan@nathanbrenton.com

    info@hiplingo.com
    postmaster@hiplingo.com
    nathan@hiplingo.com
    licensing@hiplingo.com
    press@hiplingo.com

Current rules are equivalent to:

    /^(info|postmaster)@(nathanbrenton\.com|hiplingo\.com)$/    <CONTACT_FORWARD_TARGET>

    /^(nathan|licensing|press|accounting)@hiplingo\.com$/       <CONTACT_FORWARD_TARGET>

admin@hiplingo.com intentionally does NOT match this business map. Unknown
addresses remain invalid; there is no catch-all.

postmaster@ remains a mail-domain role address even though it is not a public
marketing contact.

4C. PUBLIC RECIPIENT / RELAY BOUNDARY
----------------------------------------------------------------------

Final effective recipient-domain settings:

    virtual_alias_domains =
        nathanbrenton.com hiplingo.com srs.nathanbrenton.com

    virtual_alias_maps =
        regexp:/etc/postfix/admin-forwarding.regexp,
        regexp:/etc/postfix/contact-forwarding.regexp,
        tcp:127.0.0.1:10002

    smtpd_reject_unlisted_recipient = yes

Map responsibilities:

    admin-forwarding.regexp
        admin@hiplingo.com -> ADMIN_FORWARD_TARGET

    contact-forwarding.regexp
        explicit business/public aliases -> CONTACT_FORWARD_TARGET

    tcp:127.0.0.1:10002
        PostSRSd reverse SRS validation/decoding

Relay boundary:

    mynetworks =
        127.0.0.0/8 [::ffff:127.0.0.0]/104 [::1]/128

    smtpd_relay_restrictions =
        permit_mynetworks
        permit_sasl_authenticated
        defer_unauth_destination

Security meaning:

    - localhost is trusted for local server-generated mail
    - the public IPv4 is NOT in mynetworks
    - intended virtual recipients are accepted
    - unknown recipients in our domains are rejected
    - arbitrary unauthenticated external relay is rejected/deferred

Validated recipient policy includes:

    operations path:
        admin@hiplingo.com

    business/public path:
        info@nathanbrenton.com
        postmaster@nathanbrenton.com

        info@hiplingo.com
        postmaster@hiplingo.com
        nathan@hiplingo.com
        licensing@hiplingo.com
        press@hiplingo.com
        accounting@hiplingo.com

    random@nathanbrenton.com     SMTP 550 rejected

Representative real-message validation on 2026-08-19 confirmed both routing

6C. NGINX /.GIT / .ENV HARDENING
----------------------------------------------------------------------

What was observed:
    A public scanner requested:

        /.git/config

    and nginx returned HTTP 200.

This initially looked like a possible repository leak. A read-only audit
proved it was NOT a real .git disclosure:

    - no .git directories existed under either deployed web tree
    - no .git/config or .env files existed there
    - /.git/config response hash exactly matched / and /index.html
    - /.env response hash exactly matched / and /index.html

Cause:
    The SPA fallback:

        try_files $uri $uri/ /index.html;

    served index.html for unknown hidden-file-looking paths.

Hardening added to the application server blocks for BOTH public sites:

    location ~ /\. {
        return 404;
    }

Validated after reload:

    https://nathanbrenton.com/.git/config      -> 404
    https://nathanbrenton.com/.env             -> 404
    https://hiplingo.com/.git/config            -> 404
    https://hiplingo.com/.env                   -> 404

Additional probe examples also returned 404:

    /.env.production
    /.ssh/id_rsa
    /.foo

Important ACME detail:
    Do NOT blindly add a general /.well-known exception to the application
    vhosts after Certbot has split HTTP/HTTPS blocks. During setup, that
    exception was inserted into the wrong server block and did not help HTTP
    validation.

    The SMTP certificate instead uses its OWN dedicated port-80 vhost:

        web-prod-01.nathanbrenton.com

    with:

        location ^~ /.well-known/acme-challenge/ { ... }

    This cleanly separates SMTP-host ACME from the two application SPA
    fallbacks.

Security principle:
    Returning explicit 404 for hidden paths reduces ambiguity, avoids leaking
    hidden files if one is accidentally deployed later, and prevents SPA
    fallback from making scanner probes look successful.

6D. HIPLINGO PUBLIC-MEDIA DEPLOYMENT / SERVING PERMISSIONS
----------------------------------------------------------------------

Why this belongs in the server runbook
--------------------------------------
Hiplingo media is deployed independently from the frontend application.
metadata-editor uses an atomic staging-and-swap workflow, while nginx serves
the resulting tree read-only.

The important distinction is between deployment write permission, needed by
deploy-hiplingo-media, and public read permission, needed by nginx/www-data.

Current production boundary
----------------------------

    /var/www/hiplingo.com
        owner: root
        group: hiplingo-media-deploy
        mode:  3775
        text:  drwxrwsr-t

    /var/www/hiplingo.com/app
        owner: root
        group: hiplingo-app-deploy
        mode:  2775
        text:  drwxrwsr-x

    /var/www/hiplingo.com/published-media
        owner: deploy-hiplingo-media
        group: hiplingo-media-deploy
        normal live mode after atomic sync: 0755

The 3775 parent mode is intentional:

    2xxx = SGID
        new sibling entries inherit hiplingo-media-deploy

    1xxx = sticky bit
        group members cannot remove/rename root-owned siblings such as app

    group write
        permits the media deploy identity to create temporary siblings used
        by the atomic deployment workflow

Do NOT replace 3775 with a broad 0777-style permission. Do NOT add www-data
to hiplingo-media-deploy.

Atomic staging permission probe
-------------------------------

LOCAL CLIENT

SAFE TO PASTE: YES

    ssh hiplingo-prod '
    probe="/var/www/hiplingo.com/published-media.metadata-editor-permission-probe.$$"
    mkdir "$probe" &&
    rmdir "$probe" &&
    echo "PASS: atomic deployment staging permission"
    '

Expected:

    PASS: atomic deployment staging permission


Public-file readability
-----------------------
The private Library and the public package intentionally have different mode
requirements.

Private Library example:

    waveform-peaks.wfp -> 0600 is acceptable/private

Public package / production:

    directories        -> 0755
    files              -> 0644
    waveform-peaks.wfp -> 0644

The publication writer and deployment rsync both normalize this boundary.
This prevents a private source mode from becoming a public nginx 403 after a
future package refresh.

PUBLIC SERVER

          printf '%s\n' "$OUTPUT" >&2
          exit "$STATUS"
        fi

        if [ -n "$OUTPUT" ]; then
          /usr/bin/logger \
            -t certbot-postfix-reload \
            -- "$OUTPUT"
        fi
        ;;
    esac

    exit 0

22. SECURITY PROPERTIES
======================================================================

Mail transport / forwarding
---------------------------
- No Gmail SMTP relay, API, or app-password dependency.
- Operational/admin and business/contact destinations are logically separate.
- Direct-to-MX Postfix delivery is used for outbound mail.
- Public SMTP is IPv4-only and bound only to loopback + 45.32.88.137.
- nftables default-drop remains in force; TCP/25 is explicitly allowed.
- Unknown virtual-domain recipients are rejected.
- No catch-all aliases.
- Unauthenticated external relay is rejected.
- mynetworks trusts loopback only.
- No IMAP, POP3, submission/587, or SMTPS/465 service is exposed.

Authentication / forwarding
---------------------------
- Operational mail is DKIM-signed.
- ops.nathanbrenton.com has narrow SPF authorization and DMARC.
- Public contact forwarding uses PostSRSd.
- srs.nathanbrenton.com SPF authorizes only the production IPv4.
- Signed SRS reverse addresses are accepted; forged SRS addresses fail.
- PostSRSd lookup services are loopback-only.
- Original forwarded message content is preserved so sender DKIM can survive.
- SRS repairs forwarding envelope/SPF transport identity, not original From:
  domain SPF alignment for DMARC.

TLS
---
- SMTP/25 advertises opportunistic STARTTLS.
- Dedicated Let's Encrypt certificate matches web-prod-01.nathanbrenton.com.
- External TLS validation passed using TLS 1.3.
- Certbot deploy hook reloads Postfix after certificate renewal.
- Certbot dry-run with deploy hooks succeeded.
- Postfix's normal reload status line may be labeled by Certbot as hook
  "error output"; this is cosmetic only when renewal and Postfix checks pass.

Web hardening
-------------
- SPA fallback no longer returns HTTP 200 for hidden-file probes.
- nginx explicitly returns 404 for /.git/*, /.env, and other hidden paths.
- Audit found no physical .git/config or .env files in either deployed tree.
- SMTP-host ACME challenge serving is isolated in a dedicated nginx vhost.


Hiplingo public-media boundary
------------------------------
- /var/www/hiplingo.com is root:hiplingo-media-deploy mode 3775 so the
  dedicated media deploy identity can create atomic sibling staging paths.
- The sticky bit protects root-owned sibling entries such as app from
  rename/removal by the media deployment group.
- /var/www/hiplingo.com/app remains a separate hiplingo-app-deploy boundary.
- published-media is owned by deploy-hiplingo-media after atomic publication.
- nginx/www-data is not granted deployment-group membership.
- Public directories are normalized to 0755 and files to 0644.
- Private Library waveform mode 0600 is retained privately and is normalized
  to 0644 only when crossing into the public package.
- /media/ is the public URL prefix; /published-media/ is an internal path name.

Monitoring
----------
- Monit TCP/2812 is not exposed.
- Monit CLI uses a root-only Unix socket.
- Monit sends alerts with native SMTP to 127.0.0.1:25.
- No production server-monitor-alert EXEC helper is required.
- No Postfix maildrop sandbox exception is required for Monit alerts.
- Production service checks are alert-only.
- PostSRSd is monitored alongside Postfix and OpenDKIM.
- Daily reporting and immediate Monit alerts remain separate mechanisms.
