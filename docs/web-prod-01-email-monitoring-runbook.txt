PURPOSE
-------
Clean, known-good walkthrough for the outbound operational-email and

DESIGN DECISIONS
----------------
1. Postfix is outbound-only. This host is not an inbound mail server.
2. No Gmail SMTP relay, Gmail App Password, API, or provider-specific relay.
3. Postfix delivers directly to recipient MX servers over outbound TCP/25.
4. No inbound SMTP firewall ports are opened.
5. Recipient selection is centralized in /etc/server-monitor/config.
6. Changing ADMIN_EMAIL is intended to change the destination globally.
7. Operational sender domain: ops.nathanbrenton.com.
8. DKIM signs outbound operational mail.
9. SPF authorizes only this server IPv4 for ops.nathanbrenton.com.
10. DMARC begins in monitoring mode (p=none).
11. systemd schedules daily summaries; Monit handles condition-driven alerts.
12. Monit is alert-only for production services; no automatic restarts yet.
13. Monit CLI uses a root-only Unix control socket; TCP/2812 is not exposed.
14. Monit remains under ProtectSystem=strict. Only Postfix maildrop is added
    to its write allowlist so EXEC alerts can submit mail locally.

11. GENERIC MONIT -> POSTFIX ALERT BRIDGE
======================================================================

Executable:
    /usr/local/sbin/server-monitor-alert

Ownership:
    root:root

Mode:
    750

It receives MONIT_* environment variables and sends through local Postfix.
Sender/recipient values remain centralized in /etc/server-monitor/config.

PUBLIC SERVER

SAFE TO PASTE: YES

    sudo tee /usr/local/sbin/server-monitor-alert >/dev/null <<'EOF'
    #!/bin/bash
    #
    # Generic Monit -> Postfix alert bridge.
    #

    set -euo pipefail

    CONFIG="/etc/server-monitor/config"

    if [ ! -r "$CONFIG" ]; then
        echo "ERROR: cannot read $CONFIG" >&2
        exit 1
    fi

    . "$CONFIG"

    for variable in ADMIN_EMAIL MAIL_FROM MAIL_FROM_NAME; do
        eval 'value=${'"$variable"':-}'
        if [ -z "$value" ]; then
            echo "ERROR: $variable is not configured" >&2
            exit 1
        fi
    done

    HOST="${MONIT_HOST:-$(hostname)}"
    SERVICE="${MONIT_SERVICE:-unknown-service}"
    EVENT="${MONIT_EVENT:-monitor-event}"
    DESCRIPTION="${MONIT_DESCRIPTION:-No event description supplied}"
    EVENT_DATE="${MONIT_DATE:-$(LC_ALL=C date -R)}"

    clean_header()
    {
        printf '%s' "$1" | tr '\r\n' '  '
    }

    HOST_HEADER="$(clean_header "$HOST")"
    SERVICE_HEADER="$(clean_header "$SERVICE")"
    EVENT_HEADER="$(clean_header "$EVENT")"

    SUBJECT="[$HOST_HEADER] MONIT: $SERVICE_HEADER — $EVENT_HEADER"

    {
        printf 'From: %s <%s>\n' "$MAIL_FROM_NAME" "$MAIL_FROM"
        printf 'To: %s\n' "$ADMIN_EMAIL"
        printf 'Subject: %s\n' "$SUBJECT"
        printf 'Date: %s\n' "$(LC_ALL=C date -R)"
        printf 'MIME-Version: 1.0\n'
        printf 'Content-Type: text/plain; charset=UTF-8\n'
        printf '\n'
        printf '%s — Monit Event\n' "$HOST"
        printf '==============================\n'
        printf '\n'
        printf 'Service:     %s\n' "$SERVICE"
        printf 'Event:       %s\n' "$EVENT"
        printf 'Event time:  %s\n' "$EVENT_DATE"
        printf '\n'
        printf 'Description:\n'
        printf '%s\n' "$DESCRIPTION"
        printf '\n'
        printf 'This message was generated by the server-wide monitoring subsystem.\n'
    } | /usr/sbin/sendmail -i -f "$MAIL_FROM" "$ADMIN_EMAIL"

    echo "monitor_alert_submitted=yes"
    EOF

    sudo chown root:root /usr/local/sbin/server-monitor-alert
    sudo chmod 750 /usr/local/sbin/server-monitor-alert

    sudo bash -n /usr/local/sbin/server-monitor-alert       && echo "alert_script_syntax=valid"

Manual bridge test:

    sudo env       MONIT_HOST="web-prod-01"       MONIT_SERVICE="monitoring-pipeline-test"       MONIT_EVENT="Test alert"       MONIT_DESCRIPTION="Manual validation of the Monit-to-Postfix alert pipeline."       MONIT_DATE="$(LC_ALL=C date -R)"       /usr/local/sbin/server-monitor-alert

14. MONIT SYSTEMD SANDBOX EXCEPTION FOR POSTFIX SUBMISSION
======================================================================

Effective hardening:
    ProtectSystem=strict
    ProtectHome=yes
    PrivateTmp=yes

Original write allowlist:
    /run
    /var/lib/monit
    /var/log

Postfix local sendmail uses postdrop, which must create a queue file under:

    /var/spool/postfix/maildrop

Monit EXEC children inherit Monit's mount namespace, so the narrow exception
is required.

We intentionally do NOT disable ProtectSystem=strict.

Drop-in:
    /etc/systemd/system/monit.service.d/postfix-maildrop.conf

Content:

    [Service]

    # Keep Monit's strict filesystem sandbox.
    # Permit only local Postfix queue submission by Monit EXEC actions.
    ReadWritePaths=/var/spool/postfix/maildrop

PUBLIC SERVER

SAFE TO PASTE: YES

    sudo install -d -m 755 /etc/systemd/system/monit.service.d

    sudo tee       /etc/systemd/system/monit.service.d/postfix-maildrop.conf       >/dev/null <<'EOF'
    [Service]

    # Keep Monit's strict filesystem sandbox.
    # Permit only local Postfix queue submission by Monit EXEC actions.
    ReadWritePaths=/var/spool/postfix/maildrop
    EOF

    sudo systemctl daemon-reload
    sudo systemctl restart monit

Verify:

    systemctl show monit.service       -p ProtectSystem       -p ProtectHome       -p PrivateTmp       -p ReadWritePaths       --no-pager

Expected essentials:

    ProtectSystem=strict

ReadWritePaths includes:

    /run

21. THRESHOLD / TIMING POLICY
======================================================================

Current initial policy:

    Monit daemon interval: 120 seconds

    CPU:
        Warn >85% for 3 cycles
        Approximately 6 minutes sustained

    RAM:
        Warn >85% for 3 cycles
        Approximately 6 minutes sustained

    Root disk:
        Warn >80% for 2 cycles
        Approximately 4 minutes

    Root inodes:
        Warn >80% for 2 cycles
        Approximately 4 minutes

    Production systemd checks:
        status != 0 for 2 cycles

Caveat:
    Monit check-program checks are asynchronous, so service-state alerts can
    take longer than a simple 2 x 120-second calculation.

Recommendation:
    Leave these conservative values in place initially and tune from real
    operating experience.

No automatic restarts yet.


======================================================================
22. SECURITY PROPERTIES
======================================================================

- No Gmail/API/app-password dependency.
- Recipient provider can be changed centrally.
- Direct-to-MX Postfix delivery.
- Outbound mail DKIM-signed.
- SPF narrowly authorizes the production IPv4.
- DMARC exists on the operational subdomain.
- Postfix is not a public inbound SMTP service.
- No inbound SMTP firewall port is opened.
- OpenDKIM socket is localhost-only.
- Monit TCP/2812 is not exposed.
- Monit CLI uses a root-only Unix socket.
- Monit remains under ProtectSystem=strict.
- Only /var/spool/postfix/maildrop is added as a narrow write exception.
- Production Monit service checks are alert-only.
- Daily reporting and condition alerts are separated.
- Alert EXEC actions have a finite timeout after Section 19.
- Configuration/executables are root-owned with restrictive modes.


======================================================================
23. LIMIT OF INTERNAL MONITORING
======================================================================

If the entire VPS is powered off, unreachable, disconnected, or unable to
route outbound mail, software on that same VPS cannot send an alert describing
that outage.

Optional future improvement:
    independent EXTERNAL uptime monitoring.

That complements Monit; it does not replace it.
