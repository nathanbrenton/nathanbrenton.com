NATHANBRENTON.COM PRODUCTION DEPLOYMENT WORKFLOW
=================================================
Updated: 2026-08-24
Local source: ~/Desktop/websites/nathanbrenton.com
Production host: web-prod-01

PURPOSE
-------
Known-good production deployment walkthrough for nathanbrenton.com.

Server prerequisite:

    /var/www/nathanbrenton.com/current
        -> releases/<UTC_TIMESTAMP>

Deployment account:

    remote user: deploy-nathan

Preferred local SSH alias:

    nathan-prod

Production releases:

    /var/www/nathanbrenton.com/releases/<UTC_TIMESTAMP>/

IMPORTANT OPERATING RULE
------------------------
Treat every release directory as IMMUTABLE.

Never SSH into an existing release and edit its files in place.

All changes originate from the local source tree, are uploaded into a NEW
timestamped release, validated there, and only then promoted by atomically
repointing "current".

This provides:
    - immediate rollback;
    - no partially updated live tree;
    - safe rsync --link-dest reuse of unchanged files.


======================================================================
0. LOCAL SOURCE / PUBLICATION BOUNDARY
======================================================================

Run on: LOCAL CLIENT

Source:

    ~/Desktop/websites/nathanbrenton.com

Do NOT publish:

    .git/
    .gitignore
    .DS_Store
    .gitkeep
    README.md
    deploy/
    docs/
    scripts/
    source-assets/

Representative public payload:

    index.html
    script.js
    site-data.js
    styles.css
    assets/
    resume/Nathan-Brenton-Resume.pdf

Preferred entrypoints:

    ./scripts/deploy.sh
    ./scripts/rollback.sh

The scripts are the normal operator interface. The manual sequence below
remains the canonical diagnostic/reference workflow.

Confirmation / stdin safety:

    deploy.sh and rollback.sh use stdin-disabled direct SSH calls where
    appropriate. Do not automate their y/N prompts by piping answers.

    Supported unattended confirmation:

        ./scripts/deploy.sh --yes
        ./scripts/rollback.sh --yes

Use --yes only when the complete operation is intentionally approved.

Public permission contract:

    local deployment source root    0755
    staged/live directories         0755
    staged/live files               0644

Do not allow archive-mode rsync to propagate a private 0700 source-root or
other non-public modes into an nginx-served release.

======================================================================
2. VERIFY CURRENT PRODUCTION RELEASE
======================================================================

    ssh nathan-prod '
      printf "current="
      readlink /var/www/nathanbrenton.com/current
    '

Confirm target exists:

    ssh nathan-prod '
      ROOT=/var/www/nathanbrenton.com
      CURRENT=$(readlink "$ROOT/current") &&
      test -d "$ROOT/$CURRENT" &&
      echo "current_target_exists=yes"
    '


======================================================================
3. PREPARE DEPLOYMENT VARIABLES
======================================================================

    cd "$HOME/Desktop/websites/nathanbrenton.com"

    REMOTE="nathan-prod"
    ROOT="/var/www/nathanbrenton.com"
    CURRENT="$(ssh "$REMOTE" "readlink '$ROOT/current'")"
    LINK_DEST="$ROOT/$CURRENT"
    RELEASE="$(date -u +%Y%m%dT%H%M%SZ)"

    echo "current=$CURRENT"
    echo "link_dest=$LINK_DEST"
    echo "new_release=$RELEASE"

Verify:

    ssh "$REMOTE" \
      "test -d '$LINK_DEST' && echo 'link_dest_exists=yes'"


======================================================================
4. DRY-RUN THE PUBLIC PAYLOAD
======================================================================

    rsync -a \
      --no-owner \
      --no-group \
      --delete \
      --itemize-changes \
      --dry-run \
      --exclude='.git/' \
      --exclude='.gitignore' \
      --exclude='.DS_Store' \
      --exclude='.gitkeep' \
      --exclude='README.md' \
      --exclude='deploy/' \
      --exclude='docs/' \
      --exclude='scripts/' \
      --exclude='source-assets/' \
      --link-dest="$LINK_DEST" \
      ./ \
      "$REMOTE:$ROOT/releases/$RELEASE/"

STOP if deployment-only, private, documentation, source-asset, or VCS paths
appear in the public payload.


======================================================================
5. UPLOAD A NEW IMMUTABLE RELEASE
======================================================================

This creates a staged release and MUST NOT alter "current".

    rsync -a \
      --no-owner \
      --no-group \
      --delete \
      --itemize-changes \
      --stats \
      --exclude='.git/' \
      --exclude='.gitignore' \
      --exclude='.DS_Store' \
      --exclude='.gitkeep' \
      --exclude='README.md' \
      --exclude='deploy/' \
      --exclude='docs/' \
      --exclude='scripts/' \
      --exclude='source-assets/' \
      --link-dest="$LINK_DEST" \
      ./ \
      "$REMOTE:$ROOT/releases/$RELEASE/"

    echo "uploaded_release=$RELEASE"

Verify production is still on the previous release:

    ssh "$REMOTE" \
      "printf 'current='; readlink '$ROOT/current'"

How incremental deployment works:
    unchanged files in the new release may be hard-linked to the previous
    release through --link-dest. Changed/new files are transferred.

This is safe only because release directories are immutable.


======================================================================
6. VALIDATE THE STAGED RELEASE BEFORE PROMOTION
======================================================================

6A. Release exists

    ssh "$REMOTE" \
      "test -d '$ROOT/releases/$RELEASE' && echo 'release_exists=yes'"

6B. Inspect inventory

    ssh "$REMOTE" \
      "find '$ROOT/releases/$RELEASE' -type f -printf '%P\n' | sort"

6C. Forbidden content absent

    ssh "$REMOTE" "
      test ! -e '$ROOT/releases/$RELEASE/README.md' &&
      test ! -e '$ROOT/releases/$RELEASE/deploy' &&
      test ! -e '$ROOT/releases/$RELEASE/docs' &&
      test ! -e '$ROOT/releases/$RELEASE/scripts' &&
      test ! -e '$ROOT/releases/$RELEASE/source-assets' &&
      test ! -e '$ROOT/releases/$RELEASE/.git' &&
      test ! -e '$ROOT/releases/$RELEASE/.gitignore' &&
      echo 'forbidden_files=absent'
    "

6D. Required files present

    ssh "$REMOTE" '
      R="/var/www/nathanbrenton.com/releases/'"$RELEASE"'"
      for f in \
        index.html \
        script.js \
        site-data.js \
        styles.css \
        resume/Nathan-Brenton-Resume.pdf
      do
        test -f "$R/$f" || exit 1
      done
      echo "required_files=present"
    '

6E. No symlinks inside release

    ssh "$REMOTE" "
      if find '$ROOT/releases/$RELEASE' -type l -print -quit | grep -q .; then
        echo 'release_symlinks=FOUND'
      else
        echo 'release_symlinks=none'
      fi
    "

6F. Public permissions

    ssh "$REMOTE" "
      R='$ROOT/releases/$RELEASE'
      printf 'root_mode='
      stat -c '%a' \"\$R\"
      find \"\$R\" \
        \( -type d ! -perm 0755 -o -type f ! -perm 0644 \) \
        -printf '%m %y %P\n' |
        sort
    "

Expected:

    root_mode=755

and no permission-violation lines.

6G. Byte-for-byte source/staged comparison

    rsync -a \
      --checksum \
      --delete \
      --itemize-changes \
      --dry-run \
      --no-owner \
      --no-group \
      --exclude='.git/' \
      --exclude='.gitignore' \
      --exclude='.DS_Store' \
      --exclude='.gitkeep' \
      --exclude='README.md' \
      --exclude='deploy/' \
      --exclude='docs/' \
      --exclude='scripts/' \
      --exclude='source-assets/' \
      ./ \
      "$REMOTE:$ROOT/releases/$RELEASE/"

Expected:
    no rsync change lines.

6H. Current still unchanged

    ssh "$REMOTE" \
      "printf 'current='; readlink '$ROOT/current'"


======================================================================
7. ATOMIC PROMOTION
======================================================================

Only after staged validation passes:

    ssh "$REMOTE" '
      ROOT=/var/www/nathanbrenton.com
      RELEASE='"$RELEASE"'
      OLD=$(readlink "$ROOT/current") &&
      rm -f "$ROOT/.current-$RELEASE" &&
      ln -s "releases/$RELEASE" "$ROOT/.current-$RELEASE" &&
      mv -Tf "$ROOT/.current-$RELEASE" "$ROOT/current" &&
      printf "previous=%s\ncurrent=%s\n" \
        "$OLD" \
        "$(readlink "$ROOT/current")"
    '

No nginx reload is required merely to switch the symlink.


======================================================================
8. LIVE VALIDATION
======================================================================

HTTP:

    for url in \
      https://nathanbrenton.com/ \
      https://www.nathanbrenton.com/ \
      https://nathanbrenton.com/resume/Nathan-Brenton-Resume.pdf
    do
      printf '%s -> ' "$url"
      curl -fsS -o /dev/null -w 'http=%{http_code}\n' "$url" || echo FAILED
    done

Compare local/live index SHA-256:

    cd "$HOME/Desktop/websites/nathanbrenton.com"

    printf 'local_index='
    shasum -a 256 index.html | awk '{print $1}'

    printf 'live_index='
    curl -fsS https://nathanbrenton.com/index.html |
      shasum -a 256 |
      awk '{print $1}'

Hashes must match.

Confirm current:

    ssh nathan-prod '
      printf "current="
      readlink /var/www/nathanbrenton.com/current
    '

Browser smoke test:
    - HTTPS loads
    - layout/assets correct
    - project links work
    - resume opens
    - desktop presentation correct
    - mobile presentation correct

Keep at least the previous known-good release.


======================================================================
9. ROLLBACK
======================================================================

List releases:

    ssh nathan-prod '
      find /var/www/nathanbrenton.com/releases \
        -mindepth 1 \
        -maxdepth 1 \
        -type d \
        -printf "%f\n" |
        sort
    '

Set:

    TARGET="<PREVIOUS_GOOD_TIMESTAMP>"

Validate target exists:

    ssh nathan-prod \
      "test -d '/var/www/nathanbrenton.com/releases/$TARGET' &&
       echo 'rollback_target=present'"

Atomic rollback:

    ssh nathan-prod '
      ROOT=/var/www/nathanbrenton.com
      TARGET='"$TARGET"'
      rm -f "$ROOT/.rollback-$TARGET" &&
      ln -s "releases/$TARGET" "$ROOT/.rollback-$TARGET" &&
      mv -Tf "$ROOT/.rollback-$TARGET" "$ROOT/current" &&
      printf "current=%s\n" "$(readlink "$ROOT/current")"
    '

Validate:

    curl -fsS \
      -o /dev/null \
      -w 'rollback_https=%{http_code}\n' \
      https://nathanbrenton.com/


======================================================================
10. NORMAL FUTURE DEPLOYMENT CYCLE
======================================================================

    1. Make changes locally.
    2. Run normal project validation.
    3. Verify SSH/current release.
    4. Create a fresh UTC timestamp.
    5. Run rsync dry-run.
    6. Review publication boundary.
    7. Upload a NEW release with --link-dest.
    8. Validate required/forbidden paths.
    9. Validate no release-internal symlinks.
   10. Require directories 0755 and files 0644.
   11. Require checksum dry-run to converge.
   12. Atomically switch current.
   13. Validate public HTTPS.
   14. Compare local/live index hash.
   15. Browser smoke test.
   16. Keep a previous known-good release.


======================================================================
11. DO NOT
======================================================================

Do NOT:
    - edit an existing production release;
    - rsync directly into current;
    - publish docs/, scripts/, deploy/, source-assets/, README.md, or VCS data;
    - promote a staged release with bad 0755/0644 modes;
    - delete the previous known-good release immediately;
    - replace files manually during rollback;
    - reload nginx merely to change current;
    - weaken SSH authentication for deployment convenience.
